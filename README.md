# LaunchNexus website

Static marketing site for LaunchNexus Ltd. No build step, no dependencies —
deploys to Vercel as-is.

## Structure

    index.html              Homepage
    services.html           Services overview
    services-crm.html       Personalised CRM systems
    services-websites.html  Websites
    services-apps.html      Web & mobile apps
    work.html               Selected work / case studies
    how-it-works.html       Process and pricing approach
    about.html              About
    contact.html            Enquiry form
    thanks.html             Post-submission confirmation (noindex)
    privacy.html            Privacy notice        (DRAFT — review)
    cookies.html            Cookie notice         (DRAFT — review)
    terms.html              Website terms of use  (DRAFT — review)
    assets/site.css         Whole design system
    assets/site.js          Nav drawer, reveals, enquiry form
    api/enquiry.js          Emails enquiries to info@launchnexus.co.uk
    supabase/enquiries.sql  Optional enquiries table + RLS
    build.py                Regenerates every page from one shared shell
    sitemap.xml, robots.txt

## Editing

`index.html` is hand-written. Every other page is generated by `build.py`,
which holds the shared header, nav and footer plus each page's body. Edit
`build.py`, then:

    python3 build.py

Editing the generated .html files directly means your changes are lost on the
next build. The one exception is `index.html`, which is not generated.

## Enquiry form

The form posts to `/api/enquiry`, a Vercel serverless function that emails the
enquiry to info@launchnexus.co.uk via Resend, with `reply_to` set to the
enquirer so replying goes straight back to them. If the endpoint is
unreachable the form falls back to the visitor's email client, so an enquiry is
never silently lost.

Environment variables (Vercel → Settings → Environment Variables):

    RESEND_API_KEY   required
    ENQUIRY_TO       optional, defaults to info@launchnexus.co.uk
    ENQUIRY_FROM     optional, defaults to onboarding@resend.dev

`onboarding@resend.dev` only delivers to the Resend account owner's own
address, so ENQUIRY_FROM must be set for this to work in production.

We send from a **launchsession.co.uk** address, because that domain is already
verified in Resend and verifying a second domain requires a paid plan. This is
deliberate, not an oversight. The email only ever goes to us, and `reply_to` is
the enquirer, so replying reaches them from the normal mailbox — the sender
address is never seen by anyone outside.

    ENQUIRY_FROM = LaunchNexus enquiries <website@launchsession.co.uk>

Switch to a launchnexus.co.uk sender (which means upgrading Resend and
verifying the domain) if the site ever emails the enquirer directly — an
automated acknowledgement, a proposal link, a receipt. At that point the
sending domain is client-facing and a mismatch costs both credibility and
deliverability.

To also store enquiries, run `supabase/enquiries.sql` and set `SUPABASE_URL`
and `SUPABASE_SERVICE_ROLE_KEY`. The service-role key is used server-side only
and never reaches the browser. A storage failure is logged but won't lose an
enquiry that has already been emailed.

## Abuse controls on /api/enquiry

- 20KB request body cap, checked before parsing.
- 5 submissions per IP per 10 minutes, held in memory. Serverless instances are
  ephemeral and run in parallel, so this throttles casual abuse but is not a
  hard ceiling. Put Vercel's firewall in front of the route if that's needed.
- Honeypot field; bot submissions get a 200 and are discarded.
- The enquiries table has RLS enabled with **no policies**. Only the
  service-role key used server-side can write to it. Do not add an anon insert
  policy — it would let anyone bypass every check above.

## Known and accepted

Selected-radio tinting uses CSS `:has()`. On older iOS Safari the radio still
works and shows its checked state via `accent-color`; only the card tint is
missing. Accepted rather than restructuring the markup.
